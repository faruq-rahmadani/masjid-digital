# repository

Data access and external integrations. Implements the repository interfaces declared in `internal/usecase/interface.go`.

## What goes here

One subfolder per data source / client, for example:

- `masjid/`, `transaction/`, ...: database storage, one package per aggregate
- `memory/`: in-memory store (cache, local dev, tests)
- `<service>/`: third-party API client (e.g. a prayer time API)

## Rules

- Each subpackage exposes a `NewRepository(...)` constructor that returns a type satisfying a `usecase.*RepositoryItf`
- Accept and return `domain` types; convert DB rows / API payloads inside this layer
- No business logic: that belongs in `internal/usecase`
- Client config lives in `internal/config/schema_client.go` and is passed in from `cmd/http/main.go`

## Database repositories

The app runs on either SQLite or PostgreSQL (`app.database.driver`). Database repositories must not know which one:

- Depend on `database.Querier` from `pkg/database`, never on `*sql.DB`, pgx or sqlite directly
- Pass the request `ctx` to every call so it joins the usecase's transaction (`database.Transactor.WithTx`)
- Return `*apperror.AppError` ready for the client, so usecases can `return err` as is:
  - `database.ErrNotFound` -> `CodeNotFound`, `database.ErrUniqueViolation` -> `CodeAlreadyExists`, anything else -> `CodeInternal`
  - Put the domain sentinel (e.g. `domain.ErrUserNotFound`) in `InternalError`, so a usecase can still `errors.Is` it when it must answer differently, e.g. login hiding which phone numbers are registered

Write SQL that runs on both engines:

- `?` placeholders; they are rebound to `$1, $2, ...` on PostgreSQL
- Integer IDs generated by the database (`INTEGER PRIMARY KEY AUTOINCREMENT` on SQLite, `BIGINT GENERATED ALWAYS AS IDENTITY` on PostgreSQL), read back with `RETURNING id` since `LastInsertId` does not work on PostgreSQL
- Money as integer Rupiah (`BIGINT`), never floats
- Pass time from Go in UTC instead of `NOW()`; declare time columns as `TIMESTAMP`
- No engine-only features (`JSONB`, `ILIKE`, `LISTEN/NOTIFY`, arrays); `ON CONFLICT`, `RETURNING`, CTEs and window functions are fine

```go
package masjid

type repository struct {
	db database.Querier
}

func NewRepository(db database.Querier) usecase.MasjidRepositoryItf {
	return &repository{db: db}
}

func (r *repository) GetBySlug(ctx context.Context, slug string) (domain.Masjid, error) {
	var row masjidRow
	err := r.db.Get(ctx, &row, "SELECT id, slug, name FROM mosques WHERE slug = ?", slug)
	if errors.Is(err, database.ErrNotFound) {
		return domain.Masjid{}, apperror.New(apperror.CodeNotFound, domain.ErrMasjidNotFound, "masjid tidak ditemukan")
	}
	if err != nil {
		return domain.Masjid{}, apperror.New(apperror.CodeInternal, err, "gagal mengakses data masjid")
	}
	return row.toDomain(), nil
}
```

## Mocks for unit tests

Interfaces consumed across layers are mocked with [gomock](https://github.com/uber-go/mock). Every generated mock lives in the root `mock` package; a `//go:generate` line next to each interface writes it there. After changing an interface, regenerate them all:

```sh
go generate ./...
```

`mockgen` is a tool dependency in `go.mod`, so nothing has to be installed. Repository tests that need a real database (e.g. `database/users`) run against SQLite instead of mocks.
